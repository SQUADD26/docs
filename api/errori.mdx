title: "Errori"
description: "Un solo formato di errore per tutti gli endpoint e l'elenco chiuso dei codici."

---

Ogni errore ha la stessa forma, su tutti gli endpoint:

```json
{
  "error": {
    "code": "invalid_request",
    "message": "servono venueId, serviceDate, time e partySize",
    "details": { "fields": ["venueId", "serviceDate", "time", "partySize"] }
  }
}
```

- `code`: uno dei valori della tabella sotto. **Decidi in base a `code`**, non a `message`.
- `message`: testo leggibile in italiano, puo' cambiare.
- `details`: oggetto, sempre presente, a volte vuoto.

Lo status HTTP dipende solo da `code`.

## Codici

| Status | `code` | Significato | Cosa fare |
| --- | --- | --- | --- |
| `400` | `invalid_request` | Parametri mancanti o malformati. `details.fields` elenca quali | Correggi la richiesta |
| `401` | `unauthenticated` | Nessuna chiave | Aggiungi `Authorization: Bearer gsk_...` |
| `401` | `api_key_invalid` | Chiave sconosciuta | Controlla la chiave |
| `401` | `api_key_revoked` | Chiave revocata | Crea una chiave nuova |
| `403` | `forbidden` | Il membro della chiave non ha il permesso | Rivedi il ruolo del membro |
| `404` | `not_found` | Locale, prenotazione o ospite in coda inesistenti o non accessibili | Controlla gli id |
| `409` | `no_availability` | Non c'e' posto. `details.reason` e `details.alternatives` come in `/availability` | Proponi un'alternativa |
| `409` | `conflict` | La prenotazione e' cambiata o e' in uso | Rileggi e ritenta |
| `409` | `idempotency_in_progress` | Una richiesta con la stessa `Idempotency-Key` e' ancora in corso | Ritenta fra poco con la stessa chiave |
| `422` | `idempotency_key_reused` | Stessa `Idempotency-Key` gia' usata per un'altra operazione | Usa una chiave nuova |
| `429` | `rate_limited` | Troppe richieste al minuto per questa chiave | Rallenta e ritenta |
| `500` | `internal_error` | Errore nostro | Ritenta; se persiste, segnalalo |

## "No" non e' un errore

Due risposte negative arrivano con `200`, non come errore:

- `GET /availability` senza posto: `available: false`, `reason` e `alternatives`.
- `GET /guests/lookup` senza ospite: `found: false`. E' un ospite nuovo: chiedigli il nome.

### Motivi di indisponibilita' (`reason`)

| `reason` | Significato |
| --- | --- |
| `closed` | Il locale e' chiuso quel giorno |
| `no_shift` | Nessun turno a quell'ora |
| `after_last_seating` | Passato l'ultimo ingresso |
| `no_turn_time_rule` | Manca una regola di durata per quei coperti |
| `no_table` | Nessun tavolo libero della capienza giusta |
| `pacing_full` | Tetto coperti della fascia oraria pieno |
