## Richieste al minuto

| Ambito | Limite |
| --- | --- |
| Chiave API | Numero massimo di richieste al minuto, fissato alla creazione della chiave |

Il limite si applica per chiave, non per organizzazione: due chiavi della stessa organizzazione hanno limiti indipendenti.

Oltre il limite, l'API risponde `429`:

```json
{ "error": { "code": "rate_limited", "message": "troppe richieste per questa chiave", "details": {} } }
```

La risposta non include gli header `Retry-After` né `X-RateLimit-*`. Ripeti la richiesta con backoff esponenziale: attesa iniziale di qualche secondo, raddoppiata a ogni `429` successivo.

<Tip>
  Per ripetere una creazione dopo un `429`, usa la stessa [`Idempotency-Key`](/api/idempotenza).
</Tip>

## Vincoli sui campi

| Campo | Vincolo |
| --- | --- |
| `serviceDate` | `YYYY-MM-DD` |
| `time`, `earliestTime`, `latestTime` | `HH:MM` |
| `partySize` | Intero maggiore di zero |
| `phone` | Qualsiasi formato normalizzabile in E.164 |
| Body di `PATCH /reservations/{id}` | Almeno uno tra `serviceDate`, `time`, `partySize`, `notes` |

Un campo obbligatorio mancante, un `partySize` non valido, un `phone` non normalizzabile o un body `PATCH` senza campi modificabili restituiscono `400 invalid_request`.
